Abstract

Tiny Gateway is a computing architecture organized around Rhyming Templates: reusable patterns of organization that let information, relationships, and processes be represented and reconstructed across scales without storing every expression as an independent full object. The productized memory layer is named Tiny Footprint.

Strategic proposition. A lot of cost is paying rent on duplicated resident state so the same organizational pattern can be served many times. If operators deliver the same service with far less resident memory for that non-weight pile, they can pack more concurrent work per box, buy less memory per unit of AI service, and stretch limited accelerator supply further.

Findings (executed suite). Illustrative model: 78.7% under stated assumptions (≈94.1% of non-weight memory must be avoided for an 80% total cut if weights stay 15%). In-process workloads: structured 54.3%; cross-linked 82.4%; eight-node 86.4%; selective octave 99.5%; AI-context proxy 48.9%; aggregate B–F = 84.5% ≥ 80% with exact reconstruction. Tiny Footprint GPU live chat-stack lab (NVIDIA GeForce GTX 860M · this laptop): cuMemAlloc conventional 288 MiB → Tiny 53.6 MiB (81.4% cut); nvidia-smi peaks 313 → 85 MiB (72.8%); sessions-per-non-weight-MiB density gain ≈11.9×. Latency (materialization, with vs without Tiny Footprint): turn p50 41.8 ms without → 3.7 ms with (~11.2× faster); session bring-up p50 5.8 → 3.2 ms (~1.8×); HtoD traffic cut ~89%. Companion meters (not in pin): K signature-bucket routing; L recursive context-fold hooks; M energy-proxy depth scaling (PROXY: true); T organizational rhyme-KV (measured cells ≈14.6%; claimableShare=false until spliced resume is logit-equivalent; JSON≠KV). 4. Tiny Footprint GPU live-stack method

Live chat-serving proxy on NVIDIA GeForce GTX 860M (2 GiB GDDR; this laptop) via nvcuda.dll (cuMemAlloc, cuMemcpyHtoD, cuCtxSynchronize) and nvidia-smi peaks:

  • Weight stub retained in both modes
  • Conventional: duplicate system-pattern buffer + KV-like buffer per session
  • Tiny Footprint: one shared system-pattern buffer + compact per-session delta/state
  • Latency: wall-clock materialization with vs without Tiny Footprint (HtoD of duplicated full pile vs shared pattern + deltas); not frontier LLM decode TTFT/TPS
